# tw-research

輸入：一個股票代號（只給名稱時，用 `src.fetch.fetch_stock_info` 查代號；對到多檔就先問）。

## 步驟
1. 產生資料包：
   ```
   .venv\Scripts\python -m src.cli research <代號>
   ```
   產出 `reports/research_<代號>_<日期>.md`。完整讀完這份檔案。
2. 多空辯論（子代理都只讀這份資料包）：
   - **第一輪，同時**呼叫 `research-bull` 與 `research-bear`，各自只給資料包路徑；兩邊互相看不到對方，避免被對方帶著走
   - **第二輪**呼叫 `research-critic`，給它資料包路徑和兩邊的完整回覆，逐點查核
   - 子代理類型找不到時（新加的代理要重開工作階段才會載入），改用 general-purpose 子代理，並把 `.claude/agents/research-*.md` 的內容當作它的指示
3. 在同一份檔案最後加上「## 研究整理（多空辯論）」一節，結構固定如下：
   - **一句話現況**：用資料包裡的數字描述（不是預測）
   - **多方論點**：只留查核判定「成立」或「需打折」的，需打折的附原因；每點引用資料包數字與章節
   - **空方論點與風險**：同上
   - **被查核剔除的論點**：「引用錯誤」「無資料根據」的論點與原因（讓使用者知道哪些說法站不住）
   - **爭點**：雙方對同一份資料的不同解讀，以及要看到什麼後續資料才能分辨
   - **雙方都沒提到的重要資料**
   - **接下來值得觀察的資料**：下一次月營收公布、財報、法人連續買賣超是否延續等，說明「看到什麼代表什麼」
   - **和大盤的關係**：引用 §6 的相對報酬與 beta（說明這檔受大盤影響多大）
   - **資料限制**：新聞只有標題未查證；模型可信度（引用 §7 的準確率與「一律猜多數方向」比較）；財報與營收的公布時間落差；基本面沒有歷史版本
   - 主代理寫這一節時要自己再對一次數字；子代理的回覆是草稿，不是事實
4. 回報給使用者：一句話現況 + 多空各 2–3 個查核後成立的論點 + 最主要的爭點 + 被剔除幾點 + 報告路徑。

## 規則（必須遵守）
- 只能使用資料包裡的數字；不要用自己記得的財報、股價、新聞或目標價補資料（你的訓練資料可能過時或錯誤）
- 不寫「建議買進 / 賣出 / 加碼 / 減碼」、不給目標價或停損價、不判斷「現在適不適合進場」；多空證據要盡量對稱，不刻意導向某一邊
- 辯論沒有勝負：不寫「多方較強」「整體偏多 / 偏空」、不打分數；查核只判斷論點有沒有資料根據
- 不把 `portfolio.yaml` 或持股內容傳給子代理
- 新聞標題只能當「市場在討論什麼」的線索，不能當事實；論壇（CMoney 爆料同學會等）標註為網友意見
- 使用者若持有這檔（`portfolio.yaml`），可以提醒他對照自己在「我的持股」設定的規則，但不替他決定
- 結尾固定加上：「以上為資料整理，不構成投資建議。」
