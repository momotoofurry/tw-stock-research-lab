# 研究流程（避免自我欺騙）

目標不是「找到回測報酬更高的規則」，而是**證明一個規則在真實資料、真實成本與真實風險下有可重複的優勢**。
找不到就淘汰，不調到看起來成功為止。歷史上勝過基準也不代表未來會贏。

## 1. 事前登記（寫程式之前）

新策略先在 `docs/策略登記/YYYYMMDD_名稱.md` 寫下以下內容，之後不改；要改就另開一份新登記：

- **假設與經濟理由**：為什麼這個優勢可能存在（承擔某種風險的補償？市場反應遲緩？），什麼情況下會失效
- **股票池**：全市場候選（含下市股），每個調整日用當天的價格 / 流動性門檻決定能不能投資
- **規則與參數**：一組固定參數；鄰近參數只拿來檢查穩健性，不拿來挑最好的
- **基準**：含息 0050（主要）、同股票池等權、同股票池的簡單動能、配對的隨機選股（同股票池、同檔數、同換手率）
- **成功門檻**（全部都要過）：
  - 開發期 Sharpe 高於含息 0050，最大回撤不比 0050 深超過 10 個百分點
  - 勝過配對隨機選股：年化與 Sharpe 都在前 5%
  - 鄰近參數至少 3/4 組、前後兩段、兩倍成本都過
  - 下市持股歸零的壓力測試下仍勝過 0050
  - 不靠少數股票或單一年度：拿掉貢獻最大的 3 檔，或拿掉最好的一年，仍勝過 0050
- **要報告的風險**：最大回撤、最差月份、換手率、產業集中度、和基準的差異

## 2. 三段資料

| 階段 | 期間 | 用途 |
|---|---|---|
| 開發期 | `evaluation.holdout_start` 之前 | 形成想法、檢查穩健性；可以看很多次 |
| 驗證 | 前瞻紀錄（`data/forecast_log.csv` 之類的不可改紀錄） | 規則定稿後才開始記；不因短期好壞調參 |
| 保留期 | `holdout_start` 之後 | 規則定稿後只看一次；看過就算消耗 |

- 2025-01-01 起的保留期**已被選股排名規則消耗**（2026-10-30，`reports/holdout_log.md`）。之後任何新規則都不能把這段當成未用過的樣本外資料；新規則的樣本外證據只能來自之後才發生的前瞻紀錄。
- 開發期裡試過幾種規則都要記在登記檔裡；試越多，單次 p 值越不可信（多重比較）。

## 3. 資料可信度（每次研究前看一次 `python -m src.cli integrity`）

- 候選名單要涵蓋「任一天曾達流動性門檻」的股票（含下市）
- 下市：資料提早結束的股票以最後收盤出清（偏樂觀），報告同時給「下市持股歸零」的壓力結果
- 停牌：停牌期間無法成交
- 基本面：FinMind 只有最新版本，沒有當時公告的原始數字；只用正負號或粗略門檻的規則比較不受影響，精細數值的規則要特別保守
- 每份報告記錄設定雜湊、資料快照雜湊（逐檔清單 `*.data.json`）、git commit、套件版本

## 4. 判讀

- 「沒有足夠證據勝過對照」不等於「和對照一樣」，但都代表**不採用**
- 前瞻紀錄要累積到涵蓋不同市場環境（多頭、空頭、盤整都有）才下結論
- 任何結果都不是投資建議
